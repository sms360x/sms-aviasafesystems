## 1. Validation results

- **`db/session.py`** — async SQLAlchemy engine built with `NullPool` (one
  connection per `session_scope`); plus a single long-lived **bridge session**
  bound to one connection for the sync path. `postgres` connects via the
  transaction pooler.
- **`db/pg.py` + `db/runner.py`** — every sync query funnels through
  `pg._run_on_bridge` → `runner.run` onto the dedicated **bridge loop** (a
  different thread + event loop); each op runs in its own `begin()`. A ContextVar
  set in the request context does **not** cross that boundary by itself.
- **`middleware/auth.py`** — `get_current_user` resolves the `users` row and
  returns `uid, email, role, tenant_id` (tenant **slug**), `department`,
  `claims`. It does not carry the tenant UUID or `is_developer`.
- **`core/config.py`** — flags are plain `Settings` fields (`DEBUG`,
  `REDIS_ENABLED`), env-read by pydantic-settings.
- **`main.py`** — auth is a per-route dependency, not global middleware; no
  global DB session. The clean place to publish identity is the auth dependency.

Key facts driving the design:

- **tenant UUID resolution needs no DB lookup** — it is
  `app.db.ids.tenant_uuid(slug)` (deterministic `uuid5('tenant:'+slug)`).
- **`app.current_user` carries the Firebase uid (text)** — matching the design
  record (2C.1 §6) and the `users.uid` column; the item text labelled it "uuid",
  but the value is the uid string.
- **The role switch is the enforcement trigger** — verified in 2C.2 and again
  here: with the current GoTrue policies, `authenticated` returns **0** rows
  (and rejects writes). Hence the switch must stay OFF until 2C.3b rewrites the
  policies.

## 2. The design

### 2.1 Contextvar and where it is set

`backend/app/db/rls.py` (new) defines
`current_identity: ContextVar[dict | None]` plus `set/clear/get` helpers and
`identity_from_user(user)`. The auth dependency sets it (after
`clear_current_identity()`) as the last step of `get_current_user`. A ContextVar
is per-task: the request context is discarded when the request ends, so no
identity leaks to another request; the explicit `clear` at the start guards
against a reused context.

### 2.2 Propagation into the bridge thread

`runner.run` captures `get_current_identity()` **in the caller's context**
(synchronously) and re-applies it inside the bridge coroutine via a wrapper
`_with_identity(coro, identity)`. Both the `run_coroutine_threadsafe` path and
the nested `_NESTED_POOL` path use the wrapper. This is the explicit
propagation the naive ContextVar cannot do across threads/loops.

### 2.3 Where the listener attaches

`event.listen(engine.sync_engine, "begin", handler)` inside `get_engine()`.
One attach point covers **both** paths, because the bridge session draws its
connection from the same engine. (`after_begin` is a *Session* event; the
connection-level event that fires at transaction start is `begin`.)

### 2.4 Gating

The handler always sets the four GUCs; it executes
`SET LOCAL ROLE authenticated` only when `settings.RLS_ENFORCEMENT_ENABLED` is
true. Values are quoted SQL literals (`set_config(..., true)`); the role
statement has no parameters.

### 2.5 asyncpg / SQLAlchemy compatibility

The handler uses `conn.exec_driver_sql(...)`, which issues the statements
directly on the just-begun connection without disturbing the query that follows.
Verified on both the async session path and the bridge path (below). Statements
are transaction-local (`true`), so they reset at commit/rollback.

## 3. The change applied

| File | Change |
|---|---|
| `backend/app/core/config.py` | `RLS_ENFORCEMENT_ENABLED: bool = False` |

switch off).

### 4.4 Non-authenticated path

Seeders, workers, and migrations have no request identity, so
`current_identity` is unset and the listener returns immediately: no GUCs, no
role switch, owner connection unchanged. Confirmed by the non-authenticated
probe above (`postgres`, empty GUCs).

### 4.5 Isolation

No policy was touched, so tenant isolation is still enforced by application-code
`WHERE tenant_id = <session tenant>` filters, exactly as before. The new
per-transaction GUCs are invisible to the old (GoTrue) policies.
