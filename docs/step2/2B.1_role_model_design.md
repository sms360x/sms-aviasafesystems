# Phase 2B — Role Model Design

PHASE: 2B
ITEM: 2B.1 — read-only design pass for the role model unification
STATUS: SME-approved 2026-10-12. This is the Phase 2B design of record.
DATE: 2026-10-12
BRANCH: step2-governance

This is a read-only design pass. No code, no schema, no migrations. It maps
where roles are declared, read, written, and gated today, then defines the
canonical model for Phase 2B (workstream W2). Inputs: Step 2 Plan §W2;
`docs/step1/live_data_findings.md` (L4, L5, L8, L9, L10); 1C.1b-i (three role
sets); 1C.2 (closure defect); 1C.1 (raw VSR rule); and the 2A.5 memberships
repurpose (`docs/step2/2A.5_memberships_repurposed.md`).

> Context after 2A.5: the auth boundary reads `role`/`tenant_id` from the
> `users` row (one user = one tenant = one role). `memberships` is a
> Super-Admin reporting substrate and is not read on the auth path. Role names
> are therefore still whatever the `users.role`/Firebase claim literal holds.

---

## 1. Current state (census)

- Role literals live in **`backend/app/core/config.py`** (`AuthRole` enum +
  `Settings` role constants/lists), with a second, **internal** vocabulary in
  **`backend/app/core/rbac.py`** (`normalize_legacy_role` → module-gate names).
- The auth boundary (`app/middleware/auth.py`) builds `user["role"]` from the
  `users` row verbatim. Post-2A.5 it does **not** normalize `STATE_SMD →
  CAAN_SMD`; the `_ROLE_CLAIM_ALIASES` map is still declared but is now **dead**
  (`auth.py:57`).
- `user["role"]` is read in **~37 backend files, ~130 reads** (§3) and gated in
  **~34 files** (§5).
- Roles are written to Firebase custom claims and mirrored to `users.role`; the
  `memberships` substrate is synced by `users.upsert_user_doc`
  (create + role change) since 2A.5.
- Three mutually inconsistent role sets exist (1C.1b-i) and one wrong gate
  (1C.2); both confirmed below (§7, §8).

**Census-stop note:** the census found role strings **not** in the instruction's
list — `CAAN_INSPECTOR`, `CAAN_ADMIN`, `CAAN_AUDITOR`, `CAMO_ADMIN`,
`QA_ADMIN`, `CAMO_USER`, `QA_USER`, `SAG_MEMBER`, lowercase `regulator`/
`safety`/`auditor`, and the internal `rbac.py` names. They are mapped (§11) and
the ones that needed a decision are answered (§16). See the item report.

## 8. The closure-path defect

`app/middleware/auth.py:270-283` `get_accountable_executive`:

```python
if user.get('role') not in settings.CROSS_TENANT_ROLES and user.get('role') != "AIRLINE_ADMIN":
    raise HTTPException(403, "Accountable Executive, AIRLINE_ADMIN, or CAAN_SMD role required")
if user.get('role') == "AIRLINE_ADMIN" and not user.get('tenant_id'):
    raise HTTPException(403, "Tenant access required for AIRLINE_ADMIN")
```

- **Admits:** `CROSS_TENANT_ROLES` (`CAAN_SMD`, `STATE_SMD`, `SUPER_ADMIN`) and
  the legacy `AIRLINE_ADMIN` (with a tenant).
- **Denies:** the canonical `ACCOUNTABLE_EXECUTIVE`, and everything else.
- **Called from:** `routes/verification.py:76`
  (`POST /api/v1/hazards/{hazard_id}/closure`).

This matches 1C.2 exactly: hazard closure is **not** AE-gated — legacy Safety
Manager (`AIRLINE_ADMIN`) and regulators pass; the real AE is denied. The
canonical AE role is otherwise correct in the risk-acceptance paths
(`sram_service.AUTHORITY_ROLES`, `can_cap_service._ae_decide_async` exact AE).

**No material difference from 1C.2.** 2A.5 did not touch this function.

## 12. Target for the conflicting role sets (Q6, Q7)

The three sets (`_RAW_VSR_ROLES`, `CUSTODIAN_ROLES`, `REPORT_VIEWER_ROLES`)
**collapse to one rule, expressed once** (Q7). The single rule is
department-based (Q6):

    report_access(user, tenant):
        role == TENANT_ADMIN
        OR (role == OFFICER AND user.department == tenant.safety_department_name)

- `_RAW_VSR_ROLES` → replaced by `report_access`.
- `CUSTODIAN_ROLES` → **removed**; the custodian rule is the same rule.
- `REPORT_VIEWER_ROLES` → replaced by `report_access`.
- Cross-tenant access stays excluded (1A.7); `SUPER_ADMIN` is handled by
  platform scoping, not by this tenant-scoped rule.
- **Fallback:** when `tenants.safety_department_name IS NULL`, the rule is
  `{TENANT_ADMIN}` only (no OFFICER access). Safe by default — no tenant
  configuration, no department-based access.

The legacy `SAFETY_OFFICER` literal is gone (retired to `OFFICER` + department).
The three constants are deleted and the rule is implemented once in 2B.4.
(SME 2026-10-12.)

## Safety Department configuration (Q6)

The raw VSR rule and the custodian rule are department-based: a user with role
`OFFICER` and `department` matching the tenant's Safety Department gets raw VSR
access.

This requires a tenant-level field:

    tenants.safety_department_name text NULL

The field is set by the Super Admin when creating or editing the tenant via
`production-setup.html`.

If the field is `NULL` for a tenant, the rule falls back to: `TENANT_ADMIN`
only (no `OFFICER` access). This is safe — no tenant-specific configuration, no
department-based access.

**Placement:** the field is added in **2B.2** (schema + a config constant), or
in a dedicated item. **Choice: add it in 2B.2** (it is a prerequisite for the
2B.5 rule change and is a single additive nullable column, matching the 2A.2
additive-migration convention).

## 13. The closure-path fix (Q8)

executive)` unchanged while becoming correct.

## 16. SME answers (recorded 2026-10-12)

- **Q1 — `SAG_MEMBER`: removed (option b).** The role is retired. SAG
  membership is represented by existing roles (Department Admins, Safety
  Manager); no separate role is needed. Maps to `STAFF`.
- **Q2 — Regulator sub-roles: collapse to `STATE_SMD` (option a).**
  `CAAN_INSPECTOR`, `CAAN_ADMIN`, `CAAN_AUDITOR` all map to `STATE_SMD`. The
  regulator has one role; if sub-functions are needed, they become permissions,
  not roles.
- **Q3 — Base role: `STAFF` canonical.** `USER` is retired. `ROLE_DEFAULT`
  changes from `"USER"` to `"STAFF"`.
- **Q4 — `CAMO_*`, `QA_*`:** all map to `DEPT_ADMIN` (for `*_ADMIN` variants)
  or `STAFF` (for `*_USER` variants). The department field carries the CAMO/QA
  distinction. The earlier `*_ADMIN` pattern was superseded by
  `DEPT_ADMIN + department` for consistency across the user-creation flow.
- **Q5 — Internal `rbac.py` vocabulary:** `rbac.py` is the module-gate
  implementation that `rbac_middleware.py` calls (`has_permission`,
  `normalize_legacy_role`) — it does **not** duplicate the module-gate logic, it
  **is** it (the middleware is the caller). It serves a distinct purpose (the
  `PERMISSIONS` map + role normalization). **Keep and rename for clarity in
  2B.4.**
- **Q6 — Raw VSR rule: department-based (option a).** The rule becomes:
  `TENANT_ADMIN` **OR** (`OFFICER` with `department == the tenant's Safety
  Department`). This requires a tenant-level field identifying the Safety
  Department (`tenants.safety_department_name`; see the Safety Department
  configuration section).
- **Q7 — Custodian role set: collapsed.** `CUSTODIAN_ROLES` is **removed**. The
  custodian rule is the same as the raw VSR rule (`TENANT_ADMIN` or Safety
  Department `OFFICER`). The three conflicting role sets (`_RAW_VSR_ROLES`,
  `CUSTODIAN_ROLES`, `REPORT_VIEWER_ROLES`) collapse to one rule, expressed
  once (§12).
- **Q8 — Closure signers:** `get_accountable_executive` is **fixed**. Admit
  `ACCOUNTABLE_EXECUTIVE` only. Deny `AIRLINE_ADMIN` (retired) and
  `CROSS_TENANT_ROLES`. Keep session-derived identity (§13).
