- `pg._ID_COLUMNS` has `"tenants":"slug"` and `"regulators":"slug"`.

  (unit, no fake DB).

## 2. Decisions applied

- **Option A** — `Tenant` is the base with `polymorphic_on=kind`,
  `polymorphic_identity='operator'`; `Regulator(Tenant)` is a marker subclass
  with `polymorphic_identity='regulator'`; no `Operator` subclass.
- **All 39 columns on the base `Tenant`** (26 existing + `kind` + the 12
  regulator-only columns) so `pg.row_to_doc`/`_split_doc` (which iterate the
  shared `__table__`) map the full unified table.
- **R3 guard** on the demo-purge bulk delete.
- `regulator_id` stays a text slug.

## 3. Model change

`backend/app/db/db_models.py`:
- `Tenant` gains `kind` (Text, NOT NULL, default `'operator'`), the 12
  regulator-only columns (`operator_tenant_ids jsonb, short_name, country_code,
  country_name, domain, is_saas_customer, subscription_status,
  subscription_start, subscription_end, regulator_type, display_name, website`),
  and `__mapper_args__ = {"polymorphic_on": kind, "polymorphic_identity":
  "operator"}`.
- `Regulator(Tenant)` is now a marker subclass: no `__tablename__`, no
  re-declared columns, `__mapper_args__ = {"polymorphic_identity": "regulator"}`.

## 4. R3 guard

`backend/app/services/admin_data_service.py` (demo-purge step): the bulk delete
now filters explicitly to the discriminator:

```python
steps.append(("regulators", delete(Regulator).where(
    Regulator.kind == "regulator", Regulator.is_demo == True)))
```

Compiled SQL (verified): `DELETE FROM tenants WHERE tenants.kind = 'regulator'
AND tenants.is_demo = true AND tenants.kind IN ('regulator')` — cannot touch
operator tenants.

## 5. Test harness fix (Option X)

`tests/pg_bridge.py` is now polymorphic-aware, mirroring STI:
- New `_poly_identity(model)` returns the `polymorphic_identity` when `model`
  is an STI subclass (`mapper.inherits is not None`), else `None`.
- `_fetch_all`: injects an implicit `("kind", identity)` condition for subclass
  queries (collection still keyed by `__tablename__` = `tenants`).
- `_fetch_by`: rejects a document whose `kind` mismatches the identity.
- `_upsert`/`_insert`: stamps `kind = identity` on write when absent.
- The collection keying and the caller-facing API are unchanged; **no separate
  `regulators` collection** is introduced.

Option X (not Y) because an unfiltered `Regulator` query against the shared
collection would otherwise return **all** tenants — behaviour the real ORM does
not exhibit.
