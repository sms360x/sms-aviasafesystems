## 2. Migration

`supabase/migrations/20261010130000_membership_backfill.sql`

One idempotent `INSERT … SELECT`:

```sql
INSERT INTO public.memberships
    (user_id, tenant_id, role, effective_from, effective_to, is_active)
SELECT
    u.id,
    CASE WHEN u.role = 'SUPER_ADMIN' THEN NULL ELSE u.tenant_id END,
    u.role,
    COALESCE(u.created_at, now()),
    NULL,
    true
FROM public.users u
WHERE u.role IN ('SUPER_ADMIN','CAAN_SMD','STATE_SMD','TENANT_ADMIN',
                 'AIRLINE_ADMIN','ACCOUNTABLE_EXECUTIVE','DEPT_ADMIN',
                 'SAFETY_OFFICER','OFFICER','STAFF','USER','SAG_MEMBER')
  AND (u.role = 'SUPER_ADMIN' OR u.tenant_id IS NOT NULL)
  AND NOT EXISTS (
        SELECT 1 FROM public.memberships m WHERE m.user_id = u.id
    );
```

Applied to the live database via the app's async engine. This is a **data
migration only** — no schema, no `users`-table change, no RLS policy, no
code change.
