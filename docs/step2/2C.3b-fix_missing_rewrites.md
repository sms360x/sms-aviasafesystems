STATUS: complete

BRANCH: step2-governance

2C.3b declared 42 policies rewritten to read the session GUCs, but live showed
only 22 GUC-based; 20 were still the original `auth.jwt()` definitions. This
item fixes the re-creator that reverted them and re-applies the 20.

**2C.3c has not started.**

## 1. Diagnosis

### 1.1 Mechanism

The 2C.3b rewrites were overwritten at **runtime** by the application's own
schema bootstrap:

- `backend/app/db/schema_init.py` — `_module_b_rls_ddl()` (schema_init.py:386)
  emits, for each of the 9 `_MODULE_B_RLS_TABLES`, an unconditional
  `DROP POLICY IF EXISTS … ; CREATE POLICY … USING (… auth.jwt() …)`.
- `backend/app/db/schema_init.py` — `_MODULE_C_DDL` (schema_init.py:701) does
  the same for 11 Module C policies.
- Both are executed by `ensure_domain_schema_async()` (schema_init.py:937),
  which is reached at runtime from `app/routes/reporting.py:66`
  (`ensure_domain_schema()`) — on the CAAN/regulator report path when a report
  is written with **no effective tenant**.

The 9 + 11 = **exactly the 20 drifted policies**. The re-creation is
unconditional (`DROP` + `CREATE`, no existence guard), so every call reverts
the 2C.3b GUC definitions. The 22 policies that survived are the ones the
bootstrap does not touch (their origin is `remote_schema` / `sram_tables` /
`sms_maturity`).

There is no migration runner or CI step in this repo, and
`supabase_migrations.schema_migrations` stops at `20260905153000`, so the
re-creator is this application path, not a SQL migration.

### 1.2 Proof (rolled-back transaction)

Applying the 2C.3b definitions for the 20, then executing the bootstrap DDL,
reverts all 20:

```
after fix20        : (guc, jwt, total) = (20, 0, 20)
after schema_init  : (guc, jwt, total) = (0, 20, 20)
```

## 2. Fix

### 2.1 `schema_init.py` — the two functions

`backend/app/db/schema_init.py`:

- `_module_b_rls_ddl()` (schema_init.py:386) — the per-table `USING` / `WITH
  CHECK` now use the operator-only GUC template:
  `current_setting('app.current_role', true) = 'SUPER_ADMIN' OR tenant_id =
  NULLIF(current_setting('app.current_tenant', true), '')::uuid`.
- `_MODULE_C_ROLE_CLAUSE` (schema_init.py:696) — now
  `current_setting('app.current_role', true) = ANY (ARRAY['STATE_SMD','SUPER_ADMIN'])`.
  This constant is interpolated into the 8 cross-tenant policies, so all 8 are
  updated in one place.
- `_MODULE_C_DDL` (schema_init.py:701) — the two remaining Module C policies
  not covered by the role clause were changed inline:
  `p_module_c_aggregates_tenant_isolation` (operator-only GUC) and
  `p_caan_reports_tenant_isolation` (text-slug GUC:
  `current_setting('app.current_tenant_slug', true)`).

Only the identity predicates changed. Policy names, tables, `TO` clauses and
the `FOR` commands are preserved, with one exception below.

**Deviation — `p_module_c_aggregates_national`.** The pre-fix bootstrap emitted
it as `FOR SELECT` (role `CAAN_SMD`); the 2C.3b design of record makes it
`FOR ALL … WITH CHECK` (role `STATE_SMD`). The instruction's "preserve the FOR
command" guideline is subordinate to "pair each with its correct GUC definition
from 2C.3b", and a `FOR SELECT` here would re-introduce drift against the fix
migration after every bootstrap run. The bootstrap now emits the 2C.3b shape.

Static checks:

```
$ grep -n "auth.jwt" backend/app/db/schema_init.py        -> none
$ grep -n "current_setting" backend/app/db/schema_init.py -> the GUC definitions
```

Generated-DDL static count: `auth.jwt` occurrences = **0**,
`current_setting` occurrences = **62**.

### 2.2 The fix migration

`supabase/migrations/20261014120000_rls_policies_guc_fix20.sql` — 40 statements
(20 `DROP POLICY IF EXISTS` + 20 `CREATE POLICY`), verbatim from the 2C.3b
definitions. Dry run (per-statement savepoints, rolled back): **40 OK / 0 FAIL**.
Applied to live in a single transaction.

## 5. Follow-up (Step 3)

`schema_init.py` currently owns RLS policy definitions in parallel with
`supabase/migrations/`. That dual ownership is what caused this drift. Step 3
should make the migrations the sole source of policy definitions, either by:

1. converting `schema_init.py`'s policy DDL to a "create only if absent" guard
   (so it can never overwrite a migration-defined policy), or
2. removing the RLS policy DDL from `schema_init.py` entirely, leaving only
   table/column/index/grant bootstrap.

This reduces the risk that a future policy rewrite is silently reverted at
runtime. With 2C.3c's live-vs-repo drift test in place, any recurrence would be
caught.
