# Phase 2C Close — RLS Enforcement

STATUS: draft (not committed; awaiting review)

BRANCH: step2-governance

Phase 2C is the RLS workstream of Step 2 (workstream W3 in the Step 2 Plan).
Its purpose was to make PostgreSQL row-level security actually enforce on the
application path: carry the request identity to the database per transaction,
rewrite the GoTrue-based policies to the app-identity template, write the
missing policies, flip enforcement on, and prove it with adversarial tests, a
real-path smoke test, and a drift test. This document records the intent, the
execution item by item, the two design decisions, the enforcement proof, the
invariants now true, the residuals left behind, and what later work inherits.

---

## 3. The two design decisions (unchanged since 2C.1)

- **D7 — session-GUC identity.** Per transaction the app sets
  `app.current_tenant` (uuid), `app.current_tenant_slug`, `app.current_role`,
  `app.current_user`, `app.current_is_developer` via `set_config(..., true)`
  from a ContextVar populated by `get_current_user`, applied by the
  `after_begin` listener on both connection paths. Transaction-scoped, hence
  pooler-safe; session `SET` is never used.
- **D8 — non-owner role.** Every authenticated transaction runs
  `SET LOCAL ROLE authenticated` (SME: reuse `authenticated`, no new role).
  Owner path (migrations, seeders, maintenance — no identity, no `SET ROLE`)
  runs outside RLS, by design (Q9).

## 4. Enforcement proof

- **Flag:** `RLS_ENFORCEMENT_ENABLED = True` (`config.py:78`; default + live).
- **Mechanism observed live:** authenticated insert+read on a policy-covered
  table succeeds; cross-tenant write raises RLS `ProgrammingError`; unset/empty
  identity reads 0 rows; owner path reads/writes freely (T7/T22/T27).
- **Adversarial (T1–T24 + table coverage):** 25 passed, 3 skipped with reasons
  (T17 dept scope is application-level; T21 covered by T7; T23 covered by T6).
  No T1–T16 regression.
- **Real-path smoke (T25–T27):** write+read isolation over HTTP as real tenant
  users on two tables (`feedback`, `invites`); owner path unaffected.
- **Drift:** 5 passed; live 67 = repo 67.
- **Full suite flag ON (2026-10-15):** 6 failed / 1200 passed / 4 skipped /
  79 deselected; zero new failures (§5).

## 5. Residuals

### 5.1 Exemptions (by design, all documented in 2C.1 §12)

- Platform tables with no policy: `dead_letter_queue`, `sms_dispatches`.
- `memberships`: SUPER_ADMIN-only. `oversight_relationships`: shared
  regulator/operator/SUPER_ADMIN shape (Q7).
- Reference read-all (`USING (true)`): 7 tables.
- SUPER_ADMIN inline exemption on tenant policies (Q5, intentional).
- Regulators see Outcome-visible/Mandatory-report only, via the oversight
  predicate — never Operator-only (Q6).

### 5.2 Known test failures (do NOT block; all pre-existing)

- `test_ae_non_delegability.py::test_no_override_or_delegation_endpoint`
  (route-mount vs assertion mismatch; T3/T4 on the same route pass).
- `test_aggregation_materializer.py` ×3 (bridge-loop deadlock under load;
  `TimeoutError` from `runner.run`).
- `test_hazard_triage.py::test_rejected_closes_hazard`,
  `test_hazard_enrichment.py`, `test_risk_matrix.py`,
  `test_tenant_sms.py::TestV1RouterRegistration` (flaky-known; several passed
  in the latest run).
- Infra flakes under full-suite load (`ConnectionResetError` /
  `InterfaceError('connection is closed')`) — retry-clean, never code
  regressions to date.

### 5.3 Test hygiene target

~85 `dependency_overrides[get_current_user]` assignments across 44 files
(full list in `2C.5_test_coverage.md` §11) bypass the RLS identity and Squarely
limit what the suite proves about enforcement. T25–T27 are the first real-path
counterweight. Future hygiene item: migrate coverage toward the real auth path.

- Every RLS-enabled table has a policy except the two documented platform
  exemptions (live 67).

  (T9 green).
- Enforcement is ON on the app path and OFF on the owner path, by construction.
- Rollback is one line (`RLS_ENFORCEMENT_ENABLED` True → False).
