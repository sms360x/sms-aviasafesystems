## 2. Scope extensions (noted)

- **`backend/app/core/config.py`** — added `TENANT_KINDS` +
  `TENANT_KINDS_SERVICE_PROVIDER` (SME-approved one-file extension; the
  canonical list the item referenced but that did not exist).
- **`backend/app/services/production_seed.py`** — necessary so `kind`
  **persists** on create (`create_tenant` builds the tenant doc explicitly, so
  without this the POST would validate but not store `kind`). One line added to
  the doc; no behaviour change for existing callers (defaults to `operator`).

## 3. Endpoint added

`GET /api/v1/admin/tenant-kinds` (auth `get_admin_user`, SUPER_ADMIN):
returns `{"success": true, "kinds": settings.TENANT_KINDS_SERVICE_PROVIDER}` =
`["operator","airport","amo","ato","ans"]` (excludes `regulator`, `platform`).

## 4. Backend validation

- **Create** (`admin_create_tenant` + `TenantCreate.kind`): accept `kind`;
  validate against `settings.TENANT_KINDS`; default `operator` if absent;
  invalid → **400**.
- **Update** (`admin_update_tenant` + `TenantUpdate.kind`): accept `kind` if
  provided, validate the same way; absent → unchanged; invalid → **400**.

## 5. UI

- **`step2-tenants.html`** — title/header/card renamed to "Add Service Provider
  Tenants"; added a "Service Provider Kind" dropdown (`#tenantKind`), populated
  on load from `GET /api/v1/admin/tenant-kinds` with a local fallback constant
  (`['operator','airport','amo','ato','ans']`); `kind` included in the payload.
- **`step3-manage.html`** — same dropdown in the entity modal (`#entityKind`),
  fetched once (cached); **enabled on create**, **disabled on edit** (shows the
  current value); `kind` sent on create and on edit.
- **`step1-regulator.html`** — removed the "Operator Tenant IDs" label, input,
  and payload line (oversight is now derived from the operator side).
