## 8. Rollback procedure

Exact for the 2026-10-12 dataset (no canonical `OFFICER` existed before, so the
only rows now `OFFICER` are the migrated ones):

```sql
UPDATE public.users       SET role = 'SAFETY_OFFICER' WHERE role = 'OFFICER';
UPDATE public.memberships SET role = 'SAFETY_OFFICER' WHERE role = 'OFFICER';
```

General rollback (reverse the map) — use with care; it reverses canonical
values that may have been written legitimately after the migration, so prefer a
pre-migration snapshot for a general rollback:

```sql
UPDATE public.users SET role = CASE role
    WHEN 'STATE_SMD'   THEN 'CAAN_SMD'
    WHEN 'OFFICER'     THEN 'SAFETY_OFFICER'
    WHEN 'TENANT_ADMIN' THEN 'AIRLINE_ADMIN'
    WHEN 'STAFF'       THEN 'USER'
    WHEN 'DEPT_ADMIN'  THEN 'CAMO_ADMIN'
    ELSE role END;
```

Firebase: `scripts/migrate_role_claims.py` is forward-only; rollback re-sets the
claims (e.g. re-run the seeder that writes legacy values, or a one-off reverse
of the 3 updated uids). The 3 migrated uids are logged by the apply run.
