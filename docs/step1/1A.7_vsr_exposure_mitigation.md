## 1. Endpoint scope (Case A)

**Case A — `/api/v1/reports/` serves multiple report types.**
- `backend/app/services/report_service.py:112-124` (`_get_reports_async`): selects `Report` rows with no `report_type` filter; for cross-tenant callers it returned **all** tenant rows.
- `backend/app/routes/occurrence_reports.py:241-255` (`get_reports`): uses `get_current_user`; cross-tenant roles set `cross_tenant=True` (`report_service.py:352-358`).
- `backend/app/services/report_service.py:363-375` (`get_report_by_id`): resolves any report id; cross-tenant callers used no tenant filter.

**Question C — distinguishing field:** `reports.report_type` with values `voluntary` (VSR) and `mandatory` (MOR) (CHECK constraint `supabase/migrations/20260830130516_remote_schema.sql:500`). `is_anonymous` also exists but `report_type` is the authoritative discriminator.

## 3. Fix applied

Case A fix, exactly in `backend/app/services/report_service.py`:
- `_get_reports_async`: cross-tenant branch now adds `where(Report.report_type != "voluntary")` before the limit, so VSRs are excluded from the cross-tenant list. Non-VSR types (MOR etc.) remain visible.
- `_get_report_async`: added a `cross_tenant` parameter; when true and the row's `report_type == "voluntary"`, returns `None` (the route maps that to **404**, not 403 — existence is not confirmed).
- `get_report_by_id`: passes `cross_tenant` through.

No change to `occurrence_reports.py` (the routes delegate to the service). Same-tenant callers are unaffected (list still filters by tenant; detail still returns VSRs).

Not touched: `regulator_dashboard.py`, any schema/model, any other endpoint.
