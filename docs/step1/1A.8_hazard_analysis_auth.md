# Step 1 — Evidence 1A.8: hazard_analysis.py authentication + session-derived tenant

PHASE: 1A
ITEM: 1A.8 — Authenticate `backend/app/api/v1/hazard_analysis.py`; derive tenant from session
STATUS: closed (code finding fixed; router-unmounted residual documented)
DATE: 2026-10-09
BRANCH: step1-audit-readiness

## Finding

`backend/app/api/v1/hazard_analysis.py` exposed four write routes with **no
authentication** and a **caller-supplied `X-Tenant-Id` header**. Any internet
caller could create hazards, RCA factors, risk assessments and CAPAs in an
arbitrary tenant, and the routes fabricated an actor identity
(`safety@{tenant}.com.np`). This is item 1A.8.

## Validation results (section 1)

**1.1 / 1.2** All four routes are POST (write), none had an auth dependency,
all read the required `X-Tenant-Id` header and used it directly as the tenant:

| Route | Method | Old params | Use of header |
|---|---|---|---|
| `POST /hazards` | POST | `payload`, `x_tenant_id: Header(...)`, `service` | tenant for `create_hazard`; spoofed `user_info` |
| `POST /hazards/{id}/rca` | POST | `hazard_id`, `payload`, `x_tenant_id: Header(...)`, `service` | tenant for `add_rca_factor` |
| `POST /hazards/{id}/assessments` | POST | `hazard_id`, `payload`, `x_tenant_id: Header(...)`, `service` | tenant + spoofed `assessor` email |
| `POST /hazards/{id}/capas` | POST | `hazard_id`, `payload`, `x_tenant_id: Header(...)`, `service` | tenant for `add_capa` |

**1.3 Callers:** none reach this file. `git grep hazard_analysis` shows only
this file, comments in `hazard_service.py` ("the unmounted hazard_analysis
router"), the archived `_archive/historical/_hold/hazards/index.html`, and the
active view `public/js/views/hazard-analysis.js` — which posts to
`/api/v1/tenants/hazards`, **not** `/api/v1/hazards`. No backend route forwards
to it.

**1.4 Tests:** none existed.

**1.5 Prefix / mount:** `APIRouter(prefix="/hazards")`. The router is **not
included** in `app/api/v1/router.py` or `app/main.py` — it is **unmounted**
(also stated at `backend/app/services/hazard_service.py:14`). If it were mounted
under `/api/v1` it would land on `/api/v1/hazards`, which **is** in the RBAC
middleware `ENDPOINT_MODULE_MAP` → `module2`.

## Fix applied

File changed: `backend/app/api/v1/hazard_analysis.py` (only).

- Added `from app.middleware.auth import get_tenant_user`; removed `Header` (and
  the unused `HTTPException`) imports.
- Every route now takes `user: Dict[str, Any] = Depends(get_tenant_user)` and
  derives `tenant_id = user["tenant_id"]` from the authenticated session.
- The `X-Tenant-Id` header parameter is removed entirely — the header is no
  longer read (extra headers are ignored by FastAPI).
- Spoofed identity replaced with the real session actor via a small `_actor()`
  helper (`email`, `uid`, `role`, `department`); assessments record
  `user.get("email")` as `assessed_by`.

`get_tenant_user` is the dependency already used by the mounted hazard write
routes (`routes/hazards.py`), so this reuses the established tenant-scoping
pattern: any authenticated user with a tenant may write; cross-tenant roles
without a tenant (e.g. `CAAN_SMD`, `SUPER_ADMIN`) are rejected with 403. The
endpoint is tenant-scoped write data, so it is not treated as legitimately
cross-tenant.

## Frontend caller update

**None.** No live frontend caller reaches this router. The view
`public/js/views/hazard-analysis.js` still sends `X-Tenant-Id`, but to
`/api/v1/tenants/hazards` (a path this file does not serve), so it is not
required to change for 1A.8. The shared `public/js/api/client.js` also sends
`X-Tenant-Id` on all requests; it was deliberately left untouched (out of scope;
it targets mounted routes). See Residuals.

## Tests — `backend/tests/test_hazard_analysis_auth.py` (new, 15 tests)

Because the router is unmounted, the tests mount it on a **test-local** FastAPI
app (`include_router(router, prefix="/api/v1")`) and override
`get_tenant_user` / `get_hazard_service`. No production mount is changed.

- `test_routes_reject_unauthenticated[...]` (4) — all four routes without a
  token → **401/403**.
- `test_authenticated_session_tenant_accepted[...]` (8 = 4 routes ×
  {Part-145 officer, Safety officer}) — → **201**, and the service is called
  with the **session tenant** `fixedwing`.
- `test_header_value_is_ignored_when_it_differs_from_session` — a request with
  `X-Tenant-Id: victim-airline` still calls the service with `fixedwing`.
- `test_cross_tenant_role_without_tenant_rejected` — `CAAN_SMD` with no tenant
  → **403**; service never called.
- `test_source_does_not_accept_x_tenant_id_header` — the module does not import
  `Header`, and no route signature declares an `x_tenant_id` parameter.

This covers both workflows: the department user preparing CAPs (`OFFICER`,
Part-145) and the Safety user performing hazard/risk analysis are both accepted
and scoped to their session tenant.

## Conclusion

**Finding closed at the code level.** `hazard_analysis.py` no longer accepts a
caller-supplied tenant and no longer permits unauthenticated writes; every route
requires an authenticated session and derives the tenant from the session. Both
workflows (department CAP prep, Safety hazard/risk analysis) are preserved and
verified.

## Residuals

- **Router is unmounted.** `app/api/v1/router.py` does not include
  `hazard_analysis`, so the fixed routes are not reachable. This predates 1A.8
  (see `hazard_service.py:14`) and mounting it would need a routing change not
  in this item's scope. If/when it is mounted under `/api/v1`, it will land on
  `/api/v1/hazards` and be module-gated as `module2`.
- **Stale frontend path.** `public/js/views/hazard-analysis.js` posts to
  `/api/v1/tenants/hazards`, which no mounted router serves. This is a
  pre-existing UI/data wiring gap (likely the reason the page is effectively
  inactive); it is not introduced or worsened by 1A.8 and is not fixed here.
- The shared `public/js/api/client.js` still emits `X-Tenant-Id` on all
  requests; the changed routes ignore it. Removing it globally is out of scope.
