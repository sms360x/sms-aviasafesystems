## Conclusion

**H1 is closed by evidence.** Every SPI route carries an authentication dependency: tenant routes require `get_current_user` + tenant scope; state routes require `get_caan_user`. Unauthenticated and invalid-token calls are rejected; a non-regulator tenant user is forbidden from state routes; foreign-tenant access is blocked.

**Residual (documented, not fixed):** `/api/v1/spi/tenant/...` is **not** in `ENDPOINT_MODULE_MAP`, so it is not module-gated by the RBAC middleware; protection is route-level only. This mirrors the `/api/v1/dashboard*` gap (item 1A.4). No middleware entry was added in 1A.2 (requires SME approval per the instruction); recorded as a finding.
