## 2. Rule as enforced, per role (same tenant)

| Role | Raw VSR detail/list | Behaviour |
|---|---|---|
| `TENANT_ADMIN` / `AIRLINE_ADMIN` (Safety Manager) | allowed | 200, raw narrative + reporter metadata |
| `ACCOUNTABLE_EXECUTIVE` | denied | 403 on detail; 403 on list |
| `DEPT_ADMIN`, `OFFICER`, `SAFETY_OFFICER` | denied | 403 on detail; 403 on list |
| `USER` / `STAFF` | denied | 403 on list (detail only reached via list scope) |
| `CAAN_SMD` / `STATE_SMD` / `SUPER_ADMIN` (cross-tenant) | excluded (1A.7) | VSR detail → 404; VSR excluded from list |
| MOR / other report types | unchanged | existing per-role access applies |

## 3. Endpoints touched (route layer only)

`backend/app/routes/occurrence_reports.py`:

- `get_reports` (list, `:250-261`) — after the existing tenant-access check, a
  same-tenant caller that is not `TENANT_ADMIN`/`AIRLINE_ADMIN` now gets
  **403**. Cross-tenant roles are unchanged. The list projection
  (`_to_list_item`) already omits narrative and reporter metadata.
- `get_report` (detail, `:270-288`) — after the existing 404 handling, a
  `voluntary` report returned to a same-tenant caller that is not
  `TENANT_ADMIN`/`AIRLINE_ADMIN` now gets **403**. Cross-tenant callers never
  reach the check (the service returns `None` for a cross-tenant VSR → 404,
  1A.7). MOR/other types are unchanged.

No repository-layer, schema, or cross-tenant change was required. The rule is
enforced entirely at the route layer.

## 4. AE aggregate gap (recorded, not built)

- Required AE shape (per the work plan): count of VSRs in period; count by
  taxonomy category (roll up to "Other" when a category count < 3); count by
  status (open/closed); month-over-month trend count — and **no** narrative,
  identifiers, dates finer than month, or concerned department.
- No dedicated AE VSR aggregate endpoint exists. The only AE-scoped endpoint is
  `GET /api/v1/dashboard/ae/kpis` (`dashboard.py:313-368`), a hazard-response
  KPI strip (`avg_days_registration_to_first_action`, `hazards_received`,
  `hazards_total`, `received_rate`, `eip_awaiting_ae`, `acceptances_pending`)
  derived from `hazards` + CAPs. It returns numeric counts (no narrative) but
  does **not** provide the required VSR counts-by-category/status/trend.
- The AE dashboard (`public/dashboard/ae-dashboard.html`) fetches
  `/api/v1/reports/` as a dead fetch, not an aggregate.
- Per the instruction, no AE aggregate endpoint was built in 1C.1. This is
  deferred to **1C.1b**.
