## 2. Rule as enforced, per role (same tenant)

| Role | Raw VSR detail/list | Behaviour |
|---|---|---|
| `TENANT_ADMIN` / `AIRLINE_ADMIN` (Safety Manager) | allowed | 200, raw narrative + reporter metadata |
| `SAFETY_OFFICER` (Safety Department officer) | allowed (corrected) | 200, raw narrative + reporter metadata |
| `ACCOUNTABLE_EXECUTIVE` | denied | 403 on detail; 403 on list |
| `DEPT_ADMIN`, `OFFICER` | denied | 403 on detail; 403 on list |
| `USER` / `STAFF` | denied | 403 on list (detail only reached via list scope) |
| `CAAN_SMD` / `STATE_SMD` / `SUPER_ADMIN` (cross-tenant) | excluded (1A.7) | VSR detail → 404; VSR excluded from list |
| MOR / other report types | unchanged | existing per-role access remains |

The allowed set is the module constant
`_RAW_VSR_ROLES = set(settings.TENANT_ADMIN_ROLES) | {settings.ROLE_SAFETY_OFFICER}`
= `{AIRLINE_ADMIN, TENANT_ADMIN, SAFETY_OFFICER}`.

## 3. Endpoints touched (route layer only)

`backend/app/routes/occurrence_reports.py`:

- Module constant `_RAW_VSR_ROLES` added near the top of the file:
  `set(settings.TENANT_ADMIN_ROLES) | {settings.ROLE_SAFETY_OFFICER}`.
- `get_reports` (list) — after the existing tenant-access check, a same-tenant
  caller whose role is not in `settings.CROSS_TENANT_ROLES` and not in
  `_RAW_VSR_ROLES` now gets **403**. Cross-tenant roles are unchanged. The list
  projection (`_to_list_item`) already omits narrative and reporter metadata.
- `get_report` (detail) — after the existing 404 handling, a `voluntary` report
  returned to a same-tenant caller whose role is not in
  `settings.CROSS_TENANT_ROLES` and not in `_RAW_VSR_ROLES` now gets **403**.
  Cross-tenant callers never reach the check (the service returns `None` for a
  cross-tenant VSR → 404, 1A.7). MOR/other types are unchanged.

No repository-layer, schema, or cross-tenant change was required. The rule is
enforced entirely at the route layer.

### Role-shim choice (SAFETY_OFFICER vs OFFICER)

- `app/core/config.py` defines a dual-accept shim:
  `SAFETY_OFFICER_ROLES = ["SAFETY_OFFICER", "OFFICER"]`, and
  `app/core/rbac.normalize_legacy_role` maps **both** to `safety_manager`. That
  normalizer is only used for the module gate, not for authorization decisions.
- The auth boundary (`middleware/auth.resolve_user_context`) does **not** rewrite
  the officer role (it only maps `STATE_SMD → CAAN_SMD`), so `user["role"]` is
  the stored literal.
- The corrected rule's acceptance is explicit: `SAFETY_OFFICER` allowed,
  `OFFICER` denied. The check therefore keys on the literal
  `settings.ROLE_SAFETY_OFFICER` (`"SAFETY_OFFICER"`), **not** the dual-accept
  `SAFETY_OFFICER_ROLES` list. This is intentional for 1C.1; the shim's
  OFFICER-as-rename unification is deferred to the Step 2 role/department model
  (§10).

## 4. AE aggregate gap (recorded, not built)

- Required AE shape (per the work plan): count of VSRs in period; count by
  taxonomy category (roll up to "Other" when a category count < 3); count by

  identifiers, dates finer than month, or concerned department.
- No dedicated AE VSR aggregate endpoint exists. The only AE-scoped endpoint is

  `/api/v1/reports/` as a dead fetch, not an aggregate.
- Per the instruction, no AE aggregate endpoint was built in 1C.1. This is
  deferred to **1C.1b**.

## 8. Conclusion

`VSR_VISIBILITY_RULE = "A"` is enforced at the code level for **raw** access:
the raw VSR (list + detail) is limited to the owning tenant's Safety Manager
(`TENANT_ADMIN`/`AIRLINE_ADMIN`) and the Safety Department officer
(`SAFETY_OFFICER`); every other same-tenant role is denied (403); cross-tenant
access stays closed (1A.7). MOR/other report types are unchanged.

Deferred: the AE aggregate view (no dedicated endpoint exists) — **1C.1b**.

## 10. Future direction (Step 2)

The current rule keys raw-VSR access on the role `SAFETY_OFFICER`. In Step 2 the
role model simplifies: `SAFETY_OFFICER` is retired in favour of `OFFICER` +
department. At that point, raw-VSR access will be determined by the user's
department (Safety Department), not by their role.

To support this, Step 2 will need one of:
- a tenant-level config field: `safety_department_name`
- a department flag: `is_safety_department`

Recorded for Step 2 planning. Not implemented in Step 1.

## Correction (2026-10-17)

Raw-VSR access is granted by `can_view_raw_vsr(user)` in
`backend/app/routes/occurrence_reports.py`. The rule:

- `TENANT_ADMIN`: allowed.
- `OFFICER` with `department == 'safety'`: allowed. `'safety'` is the universal
  canonical department **code** (`config.py` `DEPARTMENT_CODES`). Tenant display
  labels (e.g. "Corporate Safety Department") are cosmetic and are **not**
  consulted.
- `SAFETY_OFFICER` literal: allowed (defensive fallback; no live users have this
  role — the 10 residue users were deleted 2026-10-17).
- All other roles: denied.

The literal-role rule described earlier in this document is superseded.
See `docs/step2/2C.7_vsr_visibility_regression_fix.md` for the full rationale
(the 1C.1 / 2B.1 §12 Q6 / 2B.4b conflict and the SME ruling).
