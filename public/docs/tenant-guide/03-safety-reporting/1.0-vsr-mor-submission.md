# Safety Reporting (VSR / MOR)

**Step:** 03 — Safety Reporting (VSR / MOR)  
**Guide:** AviaSAFE Tenant Onboarding Guide  
**Applies to:** TENANT_ADMIN, STATE_SMD, USER  
**Prerequisites:** Step 01 (Getting Started) — signed in with a valid account

---

## 1. Overview

### 1.1 Purpose
Submit **Voluntary Safety Reports (VSR)** and **Mandatory Occurrence Reports (MOR)**, the two
operational safety data sources of the platform. This step covers the full flow from submission to
risk classification and the Safety Manager's confirmation.

### 1.2 Business Context
- **VSR (Voluntary):** any employee can report a hazard or safety concern. Anonymous reporting is
  supported to encourage a Just Culture. There is no penalty for good-faith reporting.
- **MOR (Mandatory):** reportable occurrences must be captured per CAR-19. Submissions are
  authenticated and use ICAO occurrence categories.
- Every report is automatically risk-classified with the **ICAO 5×5 risk matrix**
  (`risk_index = severity × probability`, 1–25 → `Low | Medium | High | Very High`).
- An **AI assistant** (Gemini) *suggests* severity/probability with aviation-grounded explanations,
  but it **never overrides** the official assessment — the Safety Manager (`TENANT_ADMIN` or
  `STATE_SMD`) confirms the official `risk_assessment`.

### 1.3 Expected Outcome
- A successfully submitted VSR and/or MOR with an auto-computed `risk_index` and `risk_level`.
- Understanding of the AI suggestion vs. official assessment distinction.
- Knowledge of how a report becomes an official, confirmed risk assessment.

## 2. Step-by-Step UI Guide

### 2.1 Navigation
1. Log in at **[https://sms.aviasafesystems.com](https://sms.aviasafesystems.com)** .

   - VSR: `https://sms.aviasafesystems.com/report/vsr.html?tenant=<tenant-id>`
   - MOR: `https://sms.aviasafesystems.com/report/mor.html?tenant=<tenant-id>`

### 2.2 Input Matrix

| # | Field / Action | Type | Required | Constraints / Format | Notes |
|---|---------------|------|----------|---------------------|-------|
| 1 | Report type | dropdown | Yes | `vsr` / `mor` | Choose the form that matches the event |
| 2 | Title / summary | text | Yes | Concise summary of the event | |
| 3 | Description / narrative | textarea | Yes | Max ~5000 chars for AI analysis | More detail → better AI suggestion |
| 4 | Occurrence date | date | Yes | Valid date | When the event occurred |
| 5 | Location | text | No | Free text | Phase of flight / location |
| 6 | ICAO category | dropdown | Yes (MOR) | ICAO occurrence category | Required for MOR; see [HAZARD_TAXONOMY.md](../../../../docs/HAZARD_TAXONOMY.md) |
| 7 | Severity | select 1–5 | Yes | 1=Negligible … 5=Catastrophic | Auto-multiplies with probability |
| 8 | Probability | select 1–5 | Yes | 1=Extremely Improbable … 5=Frequent | Auto-multiplies with severity |
| 9 | Report anonymously | toggle | No | VSR only | Encourages Just Culture |
| 10 | Submit | action | — | — | Creates the report |

### 2.3 Execution
1. Open the VSR or MOR form for your tenant.
2. Fill the narrative and occurrence details (recommended: set Severity and Probability).
3. For MOR, select the ICAO occurrence category.
4. Toggle **"Report anonymously"** for a VSR if you prefer (identifying yourself is always safer
   for follow-up).
5. Click **"Submit"** .

### 2.4 Success Confirmation
- The report is created and appears in your report list.
- `risk_index` is auto-computed (e.g., Severity 3 × Probability 3 = `risk_index 9`,
  `risk_level Medium`).
- A background AI analysis runs shortly after submission and fills the **AI suggestion panel** on
  the report detail page.
- The **"Confirm Risk Assessment"** control is only available to the Safety Manager
  (`TENANT_ADMIN` / `STATE_SMD`) — not to `USER`.

## 3. Edge Cases

| Scenario | Expected Behaviour | Notes |
|----------|-------------------|-------|
| Submitting without severity/probability | Report saved with legacy fields; classification runs on the canonical fields | Backward compatible (design spec v1) |
| Invalid severity or probability (e.g., 6) | Request rejected with 400 | Values must be 1–5 |
| USER tries to confirm an assessment | Action absent / 403 | Only Safety Manager roles may confirm |
| Gemini key unavailable | Mock/safe AI fallback used; no failure | Expected in offline/dev environments |
| Anonymous VSR | Submitter identity withheld; report still tenant-scoped | Follow-up may be limited |

### Common Errors

| Error Message | Cause | Resolution |
|--------------|-------|------------|
| "Report must include a valid severity_level and probability_level." | One of the 1–5 fields missing/out of range | Set both values |
| 401 on submit | Session expired | Sign in again |
| 403 on submit | Account role/tenant mismatch | Contact your administrator |
